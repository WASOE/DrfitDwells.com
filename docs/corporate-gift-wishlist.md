# Corporate gift wishlist operations

The public wishlist accepts employee nominations and HR proposal requests. Nominations require an HR email or company website/contact URL and optionally an HR contact name; no employee name or email is collected. Nominations are private and never trigger automatic contact with the nominated company, though staff may follow up manually. Ops marks nominations without an HR email as needing contact research. Leads and internal notes are restricted to the existing Finance module.

Before enabling the route on a deployment, set `MONGODB_URI` or `MONGO_URI` explicitly and run `npm --prefix server run ensure:index:corporate-gift-leads -- --apply`. The endpoint refuses valid submissions if its two unique indexes are missing; it does not create them automatically. Review any index conflict or duplicate-data error instead of dropping indexes or records.

Run `npm --prefix server run ensure:index:corporate-gift-leads` without `--apply` for a read-only index listing. The required indexes are unique `requestKeys: 1` (not partial) and unique `nominationKey: 1`, partial on `nominationKey` having BSON type `string`. Verify these on the target database; passing isolated tests does not establish production index readiness.

Configure the existing SMTP service with either `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER` and `SMTP_PASS`, or `SMTP_URL`; `SMTP_SECURE` and `SMTP_TLS_SERVERNAME` are available where required. `SMTP_HOST` takes precedence over `SMTP_URL`. Set `APP_URL` to the canonical HTTPS site origin so notification emails link to the correct Ops detail. The notification lane also requires at least one active Ops admin. New records are persisted before attempting an internal email to `jose@driftdwells.com` and an admin inbox notification; neither contacts the nominated company. Logged-only email is treated as a delivery failure. Finance users can see each delivery state and retry it from the lead detail. Verify real SMTP and inbox delivery in an approved environment before release.

After deployment and index/SMTP checks, start the dedicated supervised worker with `pm2 start ecosystem.config.cjs --only driftdwells-corporate-gift-lead-worker --env production` and save the approved PM2 configuration. The worker needs the same MongoDB, SMTP and `APP_URL` configuration as the API. It polls every minute, retries failures after five minutes, and reclaims five-minute expired leases. Without it, initial attempts still happen, but failed or interrupted deliveries require a manual retry in Ops. Monitor failed delivery states and worker logs. Delivery is at least once: an SMTP success followed by a crash before recording success can produce a duplicate email.

For the built wishlist SEO checks, run `node --test client/scripts/wishlist-seo.node.cjs` after the production build. The broader SEO suites have unrelated pre-existing failures on master: `/enduro` references a JPEG payload named `.png`, `/terms/` appears in the sitemap despite the noindex test expectation, and AI-search editorial lodging/image assertions do not match the existing content. These are not wishlist routes and should be tracked separately.
